# Локальный запуск для тестирования

Как поднять приложение на своей машине, чтобы проверить новую систему аккаунтов. Один процесс отдаёт и API, и веб-приложение с одного origin — ровно так же, как на боевом сервере (см. `DEPLOYMENT.md`), поэтому CORS не мешает и всё ведёт себя как в проде.

Два сценария. **Сначала прогони сценарий 1** — он проверяет, что обновление ничего не сломает у тебя же на реальном устройстве. Это самый рискованный момент во всей фиче.

Ветка `accounts-setup-wizard-and-admin` перебазирована на актуальный `origin/main`, так что «старая версия» в сценарии 1 — это ровно то, что сейчас в основной ветке, вместе с живой синхронизацией.

---

## Подготовка (один раз)

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted/app" && flutter build web --release
```

Пересобирай эту команду каждый раз после переключения ветки — сервер отдаёт уже скомпилированные файлы, сам он их не пересобирает.

## Сценарий 1. Со старой базой — проверка обновления

**Что проверяем:** у того, кто уже пользуется приложением, после обновления НЕ должен появиться мастер первого запуска, и ничего не должно потеряться.

Флаг «мастер уже пройден» живёт в браузере (localStorage), а не на сервере. Поэтому «старая база» здесь — это браузерный профиль, который уже прошёл онбординг на старой версии кода. Порт менять нельзя: localStorage привязан к origin, и на другом порту это будет уже «другое устройство».

> ⚠️ **Этот файл существует только на ветке `accounts-setup-wizard-and-admin`.** Пока ты на `origin/main` (шаги 1–2), его в папке не будет — это нормально, он вернётся на шаге 3. Держи инструкцию открытой в отдельной вкладке или скопируй куда-нибудь, прежде чем переключаться.

**1. Собери и запусти старую версию** (актуальный `origin/main`):

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted" && git checkout origin/main && cd app && flutter build web --release
```

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted/server" && PORT=8123 DATA_DIR=../.testdata-old WEB_DIR=../app/build/web dart run bin/server.dart
```

**2. Открой http://localhost:8123 и пройди онбординг до конца** — до главного экрана. Заведи пару транзакций, чтобы потом было видно, что данные на месте. Логиниться не нужно.

**3. Останови сервер** (Ctrl+C) и вернись на новую ветку:

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted" && git checkout accounts-setup-wizard-and-admin && cd app && flutter build web --release
```

**4. Запусти новую версию на том же порту и той же папке данных:**

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted/server" && PORT=8123 DATA_DIR=../.testdata-old WEB_DIR=../app/build/web dart run bin/server.dart
```

**5. Обнови вкладку http://localhost:8123.**

Ожидаемо:
- ✅ мастер настройки **не появился**, сразу главный экран;
- ✅ транзакции из шага 2 на месте;
- ✅ в боковой панели всё кликается, ничего не залито белым.

Если появился мастер — это баг миграции, самый важный из возможных. Скажи мне.

## Сценарий 2. С чистой базой — проверка самой фичи

**Что проверяем:** мастер первого запуска, создание админа, добавление второго пользователя.

Нужно очистить и базу сервера, и хранилище браузера. Если стереть только базу, браузер всё ещё будет считать, что мастер пройден, и ты попадёшь сразу в приложение.

**1. Свежая база сервера** (порт другой, чтобы не пересекаться со сценарием 1):

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted" && rm -rf .testdata-fresh && cd server && PORT=8125 DATA_DIR=../.testdata-fresh WEB_DIR=../app/build/web dart run bin/server.dart
```

**2. Открой http://localhost:8125 в приватном окне** — это и есть самый простой способ получить чистый localStorage. Для второго пользователя понадобится ещё одно приватное окно другого браузера (или обычное окно).

**Важно: окно должно быть шире 700 px.** Боковая панель появляется только на такой ширине — а именно она раньше залипала белым и не кликалась. В узком окне ты этот баг просто не увидишь.

**3. Что проверить:**

| Шаг | Ожидаемо |
|---|---|
| Открыл приложение | Экран **«Set up this server»** (не «Sign in») |
| Создал аккаунт админа | Попал в онбординг, потом в приложение; **боковая панель живая, не блёклая** |
| Перезагрузил страницу | Ни мастера, ни онбординга, остался залогинен |
| Открыл в другом приватном окне | Теперь **«Sign in»**, а не «Set up» — настройка закрылась навсегда |
| Account → Edit profile | Имя меняется, видно на главной |
| Account → Change password | Пароль меняется; **в другом окне тебя разлогинило** |
| Account → Manage users → Add user | Показался временный пароль, его можно скопировать |
| Зашёл этим пользователем в другом окне | Работает; раздела Manage users у него **нет** |
| Кнопка «Use without an account» | Пропускает мастер, приложение полностью работает без сервера |

**Проверка оффлайна** (это требование `specs/01-local-first-invariant.md`): выключи Wi-Fi, открой приложение в новом приватном окне, дождись «Couldn't reach that server» → нажми «Use without an account» → заведи транзакцию → перезагрузи. Всё должно работать без сети.

## Остановить и убраться

Ctrl+C в терминале с сервером, либо:

```bash
lsof -ti :8123 -ti :8125 | xargs kill 2>/dev/null; echo stopped
```

Удалить тестовые базы:

```bash
cd "/Users/innokentii.burtsev/Documents/Cashew Selfhosted" && rm -rf .testdata-old .testdata-fresh
```

Они в `.gitignore`, в коммит не попадут.

## Что здесь проверить нельзя

- **Менеджеры паролей.** Ни один браузер не предложит сохранить пароль на `http://localhost` — нужен HTTPS. Это проверяется только на твоём домене после деплоя.
- **Android APK.** Собери отдельно (`flutter build apk`) — эта сборка после изменений ещё не проверялась.
- **Синхронизация между устройствами.** Нужны два реальных устройства и задеплоенный сервер.
